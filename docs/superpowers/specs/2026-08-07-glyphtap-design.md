# Glyphtap 截图工具 — 设计文档

- 日期：2026-08-07
- 状态：已批准（MVP 设计）
- 平台：Windows
- 技术栈：C# / .NET 8 / WPF
- 目标：Snipaste 类比的截图工具，第一版聚焦「区域截图 + 基础标注」；核心后续诉求为「获取截图上的文字（OCR）」，将在 V2 实现。

## 1. 项目背景与目标

开发一款 Windows 截图工具，行为类似 Snipaste：系统托盘常驻 + 全局热键随时触发截图，拖拽选区后在截图上做基础标注，确认后复制到剪贴板。用户最终目标是能从截图上提取文字信息（OCR），该能力作为 V2 核心功能，但架构在第一版即为它预留扩展点。

### 第一版（MVP）范围
- 系统托盘常驻 App + 全局热键（F1）触发截图
- 区域截图（拖拽创建选区，拖拽 / 8 手柄缩放）
- 标注工具：矩形、椭圆、箭头、画笔；提供「清除全部标注」兜底（MVP 无撤销）
- 确认（Enter 或工具栏 ✓）后合成截图并复制到剪贴板；Esc 或鼠标右键取消
- 无标注也可直接确认（纯选区截图）
- 基于虚拟屏幕的单全屏窗口截图方案
- 截图会话期间忽略重复触发热键，防止嵌套截图窗口

### 后续阶段范围（明确标注，非 MVP）
| 阶段 | 功能 | 说明 |
|------|------|------|
| V2 | OCR 文字识别 | 本地优先（Windows.Media.Ocr 离线引擎）+ 可选云端 API 混合，复用 `ITextRecognizer` 接口与 `ClipboardService.SetText`，识别结果浮窗展示、一键复制 |
| V2 | 马赛克/模糊、高亮、文本标注 | 标注工具新增类即可，架构已支持 |
| V2 | 撤销/重做 | 标注层操作栈 |
| V3 | 贴图功能 | 截图/文字钉在屏幕上常驻，需新增贴图窗口管理 |
| V3 | 截图历史、自动保存文件 | 设置面板 + 历史记录窗口 |

## 2. 技术方案选型

在三个候选方案中选择：

1. **WPF 单全屏窗口 + 虚拟屏幕坐标系（采纳）**：一个无边框透明窗口覆盖整个虚拟屏幕（所有显示器合并矩形），窗口内以 Canvas 分图层。坐标统一换算到虚拟屏幕坐标，跨屏拖选自然支持；实现简单、调试容易。需处理多屏 DPI 差异（PerMonitorV2 DPI 感知）。
2. 每屏一个全屏窗口：DPI 天然隔离，但跨屏拖选需多窗口坐标同步，MVP 复杂度不值。
3. Win32 + Direct2D 原生：性能天花板最高，开发量 2~3 倍，MVP 阶段感知不到差异。

采纳方案 1。

## 3. 体系结构

```
Glyphtap.sln
└── src/Glyphtap/                (WPF 应用，.NET 8，PerMonitorV2 DPI 感知)
    ├── App.xaml(.cs)            启动：单实例检查、初始化托盘、注册热键
    ├── Services/
    │   ├── HotKeyService       全局热键（Win32 RegisterHotKey + WndProc）
    │   ├── ScreenCaptureService 捕获虚拟屏幕位图 + 屏幕布局信息（多屏、DPI）
    │   ├── ClipboardService     写入剪贴板（MVP：SetImage；接口为后续 SetText 预留）
    │   └── TrayIconService      托盘图标 + 右键菜单（截图 / 退出）
    ├── Capture/                 截图模块（核心）
    │   ├── CaptureWindow        全屏透明窗口，覆盖整个虚拟屏幕（Topmost + 强制激活）
    │   │   ├── 背景层：暗化的屏幕截图
    │   │   ├── 选区层：拖动创建选区、拖拽 / 8 手柄缩放
    │   │   ├── 标注层：矩形 / 椭圆 / 箭头 / 画笔
    │   │   └── 工具栏层：✓ 完成 / ✗ 取消 / 清除标注 / 工具切换 / 色板 / 粗细
    │   ├── Tools/
    │   │   ├── IAnnotationTool  标注工具接口（颜色、粗细、绘制）
    │   │   ├── RectangleTool / EllipseTool / ArrowTool / PenTool
    │   ├── SelectionLogic       选区几何计算（纯逻辑，可单元测试）
    │   └── AnnotationManager    标注对象管理（新增、选中、删除、随选区移动）
    ├── OCR/
    │   └── ITextRecognizer.cs   接口定义（本版不实现，V2 接入本地/云端 OCR）
    └── Assets/                  图标资源
```

### 设计决策
- 标注工具通过共享接口 `IAnnotationTool` 实现，新增工具（马赛克、高亮、文本）只需新增一个类。
- 选区几何计算（拖拽状态机、手柄命中、坐标换算）抽成纯逻辑类 `SelectionLogic`，不依赖 UI，保证可单元测试。
- `ClipboardService` 同时提供 `SetImage` / `SetText`，OCR 版本直接复用。
- OCR 预留 `ITextRecognizer` 接口，V2 本地/云端实现不触碰现有截图流程。

## 4. 交互流程与数据流

```
按 F1（全局热键；截图会话中重复触发将被忽略）
  → HotKeyService 收到 → 通知 App
  → ScreenCaptureService 捕获虚拟屏幕位图
  → 打开 CaptureWindow（全屏、Topmost、强制激活、暗化背景显示）
  → 用户交互：
      ① 拖拽创建选区（虚线边框 + 半透明遮罩）；无标注也可直接完成
      ② 选区可整体拖动 / 8 个手柄缩放
      ③ 选择标注工具（1/2/3/4）+ 色板颜色 + 粗细
      ④ 在选区内绘制标注（标注随选区移动；可选中 + Delete 删除）
      ⑤ 工具栏：✓ 完成 / ✗ 取消 / 清除全部标注
  → Enter 或 ✓：
      按 DPI 换算为物理像素后，RenderTargetBitmap 合成（裁剪背景 + 合并标注）为位图
      → ClipboardService.SetImage → 关闭窗口 → 回到托盘常驻
  → Esc 或 鼠标右键 或 ✗：直接关闭，不写入剪贴板
```

### 交互细节

- 标注绘制限定在选区范围内，超出部分裁掉，保证合成图与预览一致。
- 画笔恒定粗细（不处理压力），箭头为「直线 + 三角头」矢量绘制。
- 标注支持「选中 + Delete 删除」、点击选中、拖动微调。
- 无撤销/重做时，工具栏提供「清除全部标注」兜底，画错可一键清空重画。
- MVP 不做撤销 / 重做（明确排除，见后续路线图）。

### 工具栏定义（截图窗口内底部浮层）

- 工具切换：矩形 / 椭圆 / 箭头 / 画笔 四个按钮（数字键 1~4 快捷切换，当前工具高亮）
- 色板：红 / 黄 / 绿 / 蓝 / 黑 / 白 六色（固定色板，MVP 不做自定义取色）
- 粗细：细（1px）/ 中（3px）/ 粗（5px）三档
- 操作：✓ 完成并复制 / ✗ 取消 / 清除全部标注

### 快捷键（截图窗口内）

- `Enter` = 完成并复制；`Esc` = 取消；鼠标右键 = 取消
- `1 / 2 / 3 / 4` = 快速切换 矩形 / 椭圆 / 箭头 / 画笔

### DPI 坐标映射（关键）

WPF 窗口坐标（DIP）与捕获位图坐标（物理像素）必须按当前屏幕 DPI 精确换算，否则多屏 / 高 DPI 下选区必然偏移：

- 捕获：`ScreenCaptureService` 按**物理像素**捕获（`CopyFromScreen` 在 PerMonitorV2 下以每屏实际 DPI 产出），记录每个屏幕的虚拟屏幕矩形（物理像素）与 DPI 缩放因子 `scale = dpi / 96`。
- 窗口：`CaptureWindow` 覆盖虚拟屏幕矩形（以 DIP 为单位，`Left/Top` 可为负值，覆盖主屏不在左上角的情形）。
- 换算：`物理像素 = DIP × scale`；窗口内任意鼠标位置先换算到虚拟屏幕 DIP 坐标，再按该屏幕的 `scale` 得到物理像素。
- 合成：以选区对应的物理像素矩形为目标，`RenderTargetBitmap` 以 96 DPI 渲染裁剪背景 + 标注，再按 `scale` 缩放到物理像素尺寸，保证合成图与屏幕原图像素一一对应、无偏移无模糊。

### 单实例行为

- App 启动时检查互斥锁（命名 Mutex）：若已有实例，弹出提示「Glyphtap 已在运行」，立即退出，不触发任何操作。

## 5. 错误处理

| 场景 | 处理 |
|------|------|
| 全局热键被占用（F1） | 托盘气泡提示「F1 注册失败」，仍可通过托盘菜单触发截图 |
| 屏幕捕获失败 | 提示后直接退出截图模式 |
| 剪贴板写入失败 | 托盘气泡提示；截图保存到 `%TEMP%\Glyphtap\` 下文件并提示路径，内容不丢失 |
| 多显示器拔插 | 每次截图时重新枚举屏幕布局，避免残留偏移 |
| 截图会话中重复按 F1 | 忽略，不叠加第二个截图窗口 |
| 启动时已有实例 | 提示「Glyphtap 已在运行」后立即退出 |
| 退出程序 | 注销全局热键、销毁托盘图标，无残留进程 |

## 6. 测试与验收标准

### 单元测试（xUnit，覆盖纯逻辑）
- `SelectionLogic`：拖拽创建选区、手柄缩放命中、坐标换算、选区最小尺寸限制
- `ScreenCaptureService`：多显示器虚拟矩形合并、DPI 缩放换算、物理像素/DIP 双向换算
- `ClipboardService`：位图编码（WIC 内存流验证）
- 标注裁剪：超出选区的标注部分被裁掉（针对合成前裁剪逻辑）

### 手动测试清单
1. 单屏 / 双屏（DPI 相同与不同）下截图，选区坐标无偏移
2. 四种标注工具绘制、选中删除、随选区拖动
3. 「清除全部标注」一键清空后重画正常
4. 无标注直接 Enter：仅截取选区原图，标注层不残留
5. Enter 完成 → 粘贴到画图 / 微信，图像与标注完整、像素不模糊
6. Esc / 右键 / ✗ 三种取消方式 → 剪贴板内容不变
7. 热键冲突场景 → 托盘提示正常
8. 截图会话中连续按 F1 → 不出现第二个截图窗口
9. 再次启动程序 → 提示已在运行，无重复实例
10. 托盘常驻：截图后程序不退出，托盘菜单可再次截图 / 退出
11. 高 DPI 屏（125% / 150%）下截图清晰度与坐标正确
12. 退出托盘 → 任务管理器无残留进程

### 成功标准
- F1 随时可截，3 秒内进入选区模式
- 标注所见即所得，合成图与预览一致
- 程序常驻托盘不碍事，退出干净（无残留进程）
